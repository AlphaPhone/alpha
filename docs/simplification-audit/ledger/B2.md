## Done

Each module's interface is the union of the methods its call sites type or call (including the `registerPlugin<any>`
sites, read by usage), checked against the Java/Kotlin `@PluginMethod` list of the Alpha plugin class and its
upstream base (`vendor/eliza`, read-only). Result shapes come from the call-site generics, corrected against the
Java `put(...)` keys where they were `Bag`/`any`. Untrusted payloads that a parser reads afterwards are `unknown`,
never `any`. Pattern C2 (types.md §2, §3.1); B2 for optional members.

Singleton rule: a singleton is exported only where no site registers the plugin with a `web:` implementation.
`platform-plugins.registerPlugin` keeps the first registration per name, so a plugin registered at several sites
without implementations resolves to the same proxy either way (AlphaTelephony's seven sites, for example).
Where a web implementation exists (13 plugins), an import-time singleton in `native/` could win the first
registration before `browser/register.ts` runs, so those modules export the interface only.

Browser-only and test-mocks-only methods (no Android `@PluginMethod`, every caller gated) are in separate
`*BrowserMethods` / `*TestMethods` types: AlphaCalendar (`edit`, `editSeries`, `removeSeries`, `editResponse`,
`joinMeeting`, `changePreferences`, `readAgenda`), AlphaDevice (`setSensor`, `setNetwork`, `setBrightness`),
AlphaVoiceCloud (`transcribeDevelopmentCloudRecording`, `synthesizeDevelopmentCloud`), AlphaNotifications
(`setAlertPreferences`, `openAppSettings`, `compose`, `focusSnapshot`), AlphaFiles (`usage`, `storageSaveMedia`),
AlphaConnection (`pauseNotificationCollection`, test-mocks only).

Members kept optional (`?`) because the web implementation lacks them and the call site guards them (U-L2 Order:
required only after the web class gains a no-op): AlphaVoiceCloud `holdSpeechEngine`/`releaseSpeechEngineHold`
(both exist on Android, so they are not phantom as U-L2 suggested), AlphaHostedResults `releaseResultQuestion`/
`withdrawResult`/`setResultsShowing`, AlphaConnection Google Workspace return trio, AlphaCloudSignIn
`cancelGoogleSignIn` (browser only), AlphaDeletions `receipt` (browser only). Made required where Android has the
method and the old optional was only an older-build guard: ElizaCamera `setCaptureMode`, Agent `cancelRequest`
and the provider/lifecycle methods, AlphaPhotos `thumbnails`, AlphaContacts `get`/`save`/`remove`,
AlphaActionJournal recovery readers.

Methods left off because their only callers are deleted features: AlphaVoiceCloud paired methods and
`synthesizeBrowserReading` (paired-voice.ts, D5), AlphaMailAttachments `openSourceReference`/
`releaseSourceReferences` (note-source-adapter.ts, D1 previous-notes chain), `saveReviewed` via
native-recovery-backup.ts (D3; the method stays for inbox-cloud-adapter), AlphaCloudSignIn
`savedSignInRecoveryStatus`/`restoreSavedSignIn` (legacy sign-in recovery, D1/U-A8), AlphaCalendar
`calendarSyncChanged`/`sync` (native-calendar-sync.ts, already deleted by A1, D4).

## Skipped

- **No module for AlphaBrowser and ElizaLocation**: their interfaces are exactly upstream `BrowserTabHostPlugin` and
  `LocationBridge`, and both have web implementations, so a module would be a pure alias with no singleton (D4).
  The migration map points the sites at the upstream types.
- **No module for AlphaReset, AlphaGmail, ElizaPasswords, AlphaCloudSpeechStream**: one call site each, already
  typed; a module would be a new abstraction for a single caller (brief: "No new abstraction for a single caller").
  types.md proposed `alpha-reset.ts` "only for uniformity" and folding AlphaCloudSpeechStream into
  alpha-voice-cloud.ts; both skipped for that reason.
- **ElizaPasswordTransfer**: deleted feature (D3).
- **`MailAttachmentPart`** (types.md §3.1): an inline Gmail part shape in inbox-cloud-adapter.ts, not a plugin
  record; left to that file's owner.
- **`Lens`** (types.md §3.1): computed by camera-adapter from `PreviewReceipt`, not a plugin result.
- **`PhotoAccess`**: not exported; it is the same native result as `LibraryAccess` (settings-adapter's copy has
  looser `string` fields). The map replaces it with `LibraryAccess`.
- **Moving singletons out of `native.ts` / `daily.ts` / `runtime/deletions.ts`**: those are existing files (not
  mine), and their plugins have web implementations; stage C re-types them with the new interfaces.
- **Record types left with their current owners and imported type-only**: `NativeResult`, `Action`, `ClockRequest`,
  `ClockResult`, `Reminder` (daily.ts), `NoteRecordingBinding`/`NoteRecordingStatus` (prototype/note-recorder.ts),
  `LocalTranscript` (runtime/local-voice.ts), `WorkflowTap` (runtime/workflow-device-contract.ts),
  `SourceRenewalTap` (runtime/source-renewal-question.ts), `LibraryChange` (runtime/photo-library.ts),
  `GoogleWorkspaceBinding`/`GoogleWorkspaceReturnPort` (runtime/google-workspace-return.ts),
  `LocalProviderMode`/`LocalProviderKey` (runtime/local-agent.ts), `CloudEnvironment` (runtime/cloud-protocol.ts).
  `daily.ts`'s `ClockResult` rename (types.md §1.1) is not B2's.
- Type-only imports from `vendor/eliza/plugins/plugin-native-calendar/src/android-definitions.ts` (alpha-calendar.ts):
  that file is not projected into `.eliza/client-features`; the repo already imports vendor types this way
  (native.ts, passwords/). Read-only, erased at build.
